# 维护活动与责任线索

识别用户指定的本地仓库，先记录当前分支、HEAD、历史是否浅克隆及分析时间窗。默认近 180 天；不要为补足历史自行联网 fetch。

使用本技能目录下相对路径 `../../scripts/ownership-map.mjs`，将路径解析为绝对路径后通过 DSH 的正常 shell 工具执行。脚本只读取 Git 元数据，不修改工作区、Git 配置或远端。

```sh
node /absolute/plugin/scripts/ownership-map.mjs --repo /absolute/repo --since 2026-05-03 --out /absolute/workspace/ownership.json
```

日期是示例，按本次任务的时间窗设置。输出文件必须为新文件。没有 `--out` 时屏幕只展示前 30 个文件；完整结果需要保存。默认最多 1000 个非合并提交，可用 `--max-commits` 调整至最多 10000。

解释结果前检查 `historyTruncated`、`shallowRepository`、排除的机器人/大提交以及时间窗内没有历史的文件数量。代码当前存在但无历史，不等于无人维护。仓库没有提交时说明缺少数据。

按标记找出活动集中、敏感路径单一贡献者和较久未变更的文件。每个结论引用路径、提交样本、时间窗和触及次数。指出这里的“触及”是提交次数；提交身份经过 `.mailmap`，邮件只生成散列 ID，显示姓名仍属于报告内容。大规模变更超过 100 个路径默认排除，重命名路径不追溯。

如用户希望对照 CODEOWNERS，读取实际文件再比较；CODEOWNERS 的正式责任与历史提交活动是两种证据，脚本不会解析或验证其匹配规则。不得把贡献者排名当成人员绩效、知识水平或安全漏洞结论。

交付：高优先级文件、可联系的审阅者线索、证据、分析限制及报告位置。若用户要图表，使用现有可视化能力绘制，并保留原始 JSON；本技能本身不提供交互图界面。
