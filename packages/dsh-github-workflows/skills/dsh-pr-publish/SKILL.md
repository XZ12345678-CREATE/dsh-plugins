# 提交与 Draft PR

确认本次用户请求包括哪些步骤：本地提交、推送、创建 PR 或更新现有 PR。沿用已有授权。缺少目标仓库且无法从当前上下文判断时才询问。

先查看当前分支、HEAD、`git status --short --untracked-files=all`、暂存和未暂存差异，以及远端名称。远端地址可能含凭据，不把原始地址输出到报告。存在 detached HEAD、混合改动或部分暂存时，先确定本次文件/片段范围；不得用 `git add -A` 顺带提交其他工作。

检查待发布文件中的凭据、私人资料、构建缓存和第三方许可。保留必须随分发提供的版权声明；自己的新增贡献可以单独署名。运行与实际改动有关的检查，描述未执行的项目，不伪造结果。

使用用户选择的分支或为当前任务创建清晰命名的分支。按选定范围暂存、复核 staged diff 后提交。不要跳过仓库已有 hooks，不默认强推、合并或删除分支。

推送前确认目标远端与分支；对 fork PR 使用正确的目标仓库、base 和 head。先查询是否已有对应 PR，避免重复创建。默认新 PR 为 Draft，除非用户要求其他状态。

PR 标题与正文说明具体问题、改变后的行为和实际验证，包含必要限制。正文通过工具的结构化参数或临时文件传递，保留真正换行，不将用户文字插入可执行 shell 字符串。

发布后读取远端结果，交付 commit、分支、PR 链接、验证情况与尚未执行的步骤。遇到权限或网络失败就说明实际状态；重试写操作前先核实是否已经成功。
